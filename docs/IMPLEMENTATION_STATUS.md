# 현재 구현 상태

기준일: 2026-09-17

이 문서는 저장소의 현재 코드를 기준으로 실제 동작과 제한사항을 정리한다. 제품 범위는 [제품 요구사항](PRD.md), 내부 구조는 [아키텍처](ARCHITECTURE.md), 화면 동작은 [UI 명세](UI_SPEC.md), 발표 절차는 [데모 시나리오](DEMO_SCENARIO.md)를 참고한다.

## 기술 구성

- 프론트엔드: React, TypeScript, Vite, React Flow
- 백엔드: FastAPI, LangGraph
- 저장소: 애플리케이션 데이터용 `backend/demo.db`, LangGraph 체크포인트용 `backend/checkpoints.db`
- 모델 호출: OpenAI Responses API 또는 결정론적 리허설 모드
- 지도: OpenStreetMap 임베드

프론트엔드와 백엔드는 각각 하나의 프로세스로 실행한다. 별도 메시지 브로커, 작업자 프로세스, 실제 MCP 서버, 운영 인증 체계는 사용하지 않는다.

## 역할과 화면

| 역할 | 기본 화면과 메뉴 | 현재 가능한 작업 |
| --- | --- | --- |
| 파주지역 분석관 | 대시보드, 두 빌더와 레지스트리, 실행 모니터링, 상황판, 사용 매뉴얼 | 파주시 센서 입력, 본인 워크플로우·에이전트 관리, 지역 보고서 승인 |
| 정보·작전 참모 | 대시보드, 두 빌더와 레지스트리, 실행 모니터링, 상황판, 사용 매뉴얼 | 본인 워크플로우·에이전트 관리, 승인 지역보고 종합, 지휘관 보고서 승인 |
| 지휘관 | 상황판, 기본 에이전트, 사용 매뉴얼 | 최종 보고 열람, 지도 아래 내장된 기본 에이전트 채팅, 역할 기본 에이전트 실행 |
| 행정병 | 대시보드, 두 빌더와 레지스트리, 실행 모니터링, 사용 매뉴얼 | 휴가 신청 입력, 본인 워크플로우·에이전트 관리, 휴가 검토·승인과 모의 인트라넷 등록 |

로그인은 비밀번호가 없는 고정 역할 선택 방식이다. 세션은 메모리에만 있으므로 새로고침하면 다시 로그인 화면으로 이동한다. 역할을 바꾸면 `/api/session`을 다시 호출하고 대시보드로 이동한다.

분석관의 센서 입력과 행정병의 휴가 입력은 좌측 메뉴가 아니라 대시보드 헤더의 보조 버튼으로 연다. 다른 역할이 해당 URL에 직접 접근하면 대시보드로 돌아간다.

## 워크플로우 빌더

분석관, 참모, 행정병에게 각각 여섯 개의 기본 노드를 제공한다.

### 분석관

```text
감시 센서 이벤트
→ 이벤트 조건 확인
→ 작전 정보 조회
→ 위협 분석·초안 생성
→ 분석관 검토·승인
→ 지역 보고서 발행
```

### 정보·작전 참모

```text
승인 지역보고 접수
→ 승인 지역보고 수집
→ 접경지역 작전상황 조회
→ 위협 종합·초안 생성
→ 참모 검토·승인
→ 지휘관 보고서 발행
```

### 행정병

```text
정기 휴가 신청 접수
→ 잔여 휴가 조회
→ 부대 일정 조회
→ 휴가 신청 요약 생성
→ 행정병 검토·승인
→ 부대 인트라넷 등록
```

빌더에서는 노드 추가·삭제, 위치 이동, 연결 변경과 일부 노드 설정 편집이 가능하다. AI 노드는 모델과 시스템 프롬프트를, 분석관 필터 노드는 최소 신뢰도와 최소 탐지 개체 수를 편집할 수 있다. 팔레트와 설정 패널은 각 노드에 연결된 데이터 또는 외부 시스템과 `MOCK` 여부를 표시한다.

현재 생명주기는 `DRAFT`와 `PUBLISHED` 두 가지다. `SUSPENDED` 상태와 별도 배포 승인 절차는 구현하지 않았다. 게시할 때 정의 전체를 `agent_versions`에 저장하고, 실행은 시작 시점의 정의 스냅샷과 버전을 고정한다.

검증기는 다음 항목을 확인한다.

- 빈 그래프와 중복 노드 ID
- 존재하지 않는 노드를 가리키는 연결
- 연결된 시작 노드가 정확히 하나인지 여부
- 승인 노드와 발행 또는 등록 노드 존재 여부
- 시작점에서 승인·발행 노드에 도달할 수 있는지 여부

순환 그래프 일반 검출, 역할별 노드 타입의 서버 측 세밀한 검증, 정적 입출력 타입 검사는 아직 구현하지 않았다.

워크플로우 레지스트리의 검색창과 필터 버튼, 실행 목록의 검색창과 상태 필터는 현재 시각 요소이며 실제 필터링 로직은 연결되어 있지 않다.

## 실행과 승인

저장된 정의는 실행 시 LangGraph `StateGraph`로 컴파일된다. 승인 노드는 `interrupt()`로 중단하고 `Command(resume=...)`로 같은 실행을 재개한다. 실행 상태와 노드별 입력·출력 요약은 SQLite에 저장한다.

지원하는 결정은 다음과 같다.

- `APPROVE`: 초안을 그대로 승인
- `EDIT_APPROVE`: 수정한 내용을 승인
- `REJECT`: 보고서 또는 인트라넷 등록 없이 종료

승인 패널은 실행 상세 화면에서 대기 중인 실행을 열었을 때 표시된다. 현재 빌더 화면 자체에는 승인 패널이 나타나지 않는다. 실행 상세는 약 1.8초, 실행 목록은 약 2초 간격으로 상태를 다시 조회한다.

실행 조회 API의 역할별 제한은 데모 수준이다. 승인 처리와 소유 워크플로우 편집에는 역할 검사가 적용되지만, 운영 환경 수준의 전체 RBAC·ABAC는 구현하지 않았다.

## 보고서 연결 흐름

분석관 승인 후 `REGIONAL` 보고서를 저장하고 `report_events`에 이벤트를 만든다. 이 이벤트는 게시된 참모 워크플로우 하나를 시작하며, 분석관 실행에는 자식 실행 ID가 연결된다.

참모 승인 후 `COMMANDER` 보고서를 저장하고 지휘관용 `새 지휘관 보고서 도착` 알림을 만든다. 지휘관 보고서는 다시 참모 워크플로우를 시작하지 않는다. 연천군과 철원군의 승인 지역 보고서는 초기 데이터로 제공한다.

중복 방지는 다음 DB 제약을 사용한다.

- 실행당 승인 요청 한 건
- 실행당 최종 보고서 한 건
- 지역 보고서당 보고 이벤트 한 건
- 휴가 신청당 인트라넷 등록 한 건

별도 이벤트 작업자나 재시도 큐는 없으며, 지역 보고 승인 요청 안에서 참모 실행을 바로 만든다.

## ReAct 에이전트

각 역할에는 두 개의 게시된 시스템 기본 에이전트가 있다.

- `GENERAL DEFAULT`: 역할에 허용된 전체 연동 사용
- `MISSION DEFAULT`: 역할별 대표 임무에 필요한 연동만 사용

임무 특화형은 분석관 징후 상관분석, 참모 대응 우선순위, 지휘관 지휘결심 검토, 행정병 근무편성 충돌 점검을 담당한다. 시스템 기본 에이전트는 편집·삭제할 수 없다.

분석관·참모·행정병은 커스텀 에이전트를 만들 수 있다. 연결할 데이터·외부 시스템, 모델, 시스템 프롬프트와 최대 반복 횟수 5~8회를 설정한 뒤 게시한다. 지휘관은 커스텀 에이전트를 만들지 못하고 기본 에이전트만 실행한다.

실행 중 모델은 매 반복마다 연결된 도구 또는 최종 응답을 선택한다. 런타임은 역할별 허용 도구, 중복 호출, 반복 횟수와 일부 종합 도구의 선행 입력을 검사한다. 모든 연결 도구를 고정 순서로 호출하지 않으며, 최근 대화만으로 답할 수 있으면 도구 없이 종료할 수 있다.

채팅은 사용자·에이전트별 세션으로 저장한다. 같은 세션의 최근 완료 3턴만 다음 요청의 컨텍스트로 전달한다. 세션 목록에는 대화 제목 대신 `2026.09.16 시작`과 같은 시작일과 턴 수를 표시한다. 세션을 삭제하면 연결된 실행과 이벤트도 함께 삭제한다.

요청 접수, 공개 가능한 판단 요약, 도구 관찰, 응답 청크와 완료 상태는 NDJSON으로 스트리밍한다. 과거 세션을 다시 열면 사용자 요청과 최종 응답은 복원하지만, 이전 실행의 단계별 타임라인은 채팅 화면에 다시 채우지 않는다. 실행 중 연결이 끊긴 스트림을 이어받는 기능과 에이전트 HITL은 없다.

## 지휘관 상황판

지휘관의 `/dashboard`는 별도 대시보드가 아니라 상황판이다. 표시 순서는 다음과 같다.

1. 파주·연천·철원 선택이 가능한 OpenStreetMap 지도
2. 지도 아래에 내장된 `GENERAL DEFAULT` 지휘관 기본 에이전트 채팅
3. 최신 참모 종합 판단과 보고서 도착 알림

기존 하단 카드형 에이전트 레지스트리 영역은 제거했다. 좌측의 `기본 에이전트` 메뉴에서는 지휘관의 범용·임무 특화 기본 에이전트 목록과 독립 채팅 화면을 계속 사용할 수 있다.

지휘관에게 원시 센서 이벤트나 승인 전 초안을 표시하지 않는다. 지도 지역 상태는 최신 지휘관 보고서의 `source_report_ids`가 가리키는 승인 지역 보고서를 기준으로 한다. 보고서 도착 알림을 누르면 읽음 시각을 저장하고 읽기 전용 보고서 상세를 연다.

## 행정병 흐름

행정병이 휴가 신청을 접수하면 고정된 잔여 휴가 12일과 부대 일정 예시를 실행 입력에 포함한다. AI가 승인용 요약을 생성한 뒤 행정병 승인에서 중단한다. 승인하면 휴가 신청 상태를 `REGISTERED`로 바꾸고 모의 인트라넷 등록을 한 건 저장한다. 반려하면 등록하지 않고 실행을 `REJECTED`로 종료한다.

## 모델 설정

코드의 기본값은 다음과 같다.

```dotenv
OPENAI_MODEL=gpt-4.1-mini
OPENAI_ALLOWED_MODELS=gpt-4.1-mini,gpt-5-mini
```

프로젝트 루트 `.env`의 `OPENAI_MODEL`이 있으면 코드 기본값을 덮어쓴다. `OPENAI_ALLOWED_MODELS`에는 추가 허용 모델을 쉼표로 지정한다. 기본 실행 모드는 OpenAI Responses API이며, `DEMO_MODEL_MODE=deterministic`으로 설정하면 외부 호출 없이 고정 응답을 사용한다.

API 키는 백엔드 환경에서만 읽고 워크플로우·에이전트 정의나 브라우저 저장소에는 넣지 않는다.

## 실행과 초기화

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

```powershell
cd frontend
npm install
npm run dev
```

브라우저에서 `http://localhost:5173`을 연다. 데이터 초기화가 필요하면 백엔드를 종료한 뒤 다음 데모 DB 파일만 삭제하고 다시 시작한다.

- `backend/demo.db`
- `backend/checkpoints.db`
- `backend/checkpoints.db-shm`
- `backend/checkpoints.db-wal`

프로젝트 루트의 `.env`는 삭제하지 않는다.

## 아직 구현하지 않은 항목

- 운영 인증, 세밀한 권한 정책과 감사 체계
- 실제 센서·데이터 패브릭·부대 시스템·MCP 서버 연동
- `SUSPENDED` 생명주기와 배포 승인
- 검색·필터 UI의 실제 동작
- 순환 그래프와 정적 입출력 타입 검증
- 장기 기억, 다중 에이전트 협업, 에이전트 HITL
- ReAct 스트림 재접속과 과거 단계 타임라인 복원
- 고급 군사 GIS 레이어
