# 사용자 화면 명세

제품 범위는 [제품 요구사항](PRD.md), 내부 구조는 [아키텍처](ARCHITECTURE.md), 현재 구현 여부는 [현재 구현 상태](IMPLEMENTATION_STATUS.md), 발표 절차는 [데모 시나리오](DEMO_SCENARIO.md)를 참고한다.

## 디자인 원칙

- 데스크톱 발표 화면을 우선하며 최소 폭은 1180px로 둔다.
- 흰색 패널, 옅은 회색 배경, 절제된 테두리와 진한 본문 글자를 사용한다.
- 상태 색상은 텍스트와 함께 사용해 색상만으로 의미를 전달하지 않는다.
- 업무 명칭은 한국어로 표시하고 API·상태·모델 식별자만 필요한 범위에서 영문을 유지한다.
- 워크플로우 노드에는 Python, SDK 또는 LangGraph 내부 용어 대신 업무 용어를 사용한다.

## 화면과 경로

| 화면 | 경로 | 접근 역할 |
| --- | --- | --- |
| 역할 선택 로그인 | `/login` | 전체 |
| 대시보드 | `/dashboard` | 분석관·참모·행정병 |
| 지휘관 상황판 | `/dashboard` | 지휘관 |
| 워크플로우 빌더 | `/builder`, `/agents/:id/builder` | 분석관·참모·행정병 |
| 워크플로우 레지스트리 | `/agents` | 분석관·참모·행정병 |
| 에이전트 빌더 | `/react-agent-builder`, `/react-agents/:id/builder` | 전체 조회, 커스텀 편집은 분석관·참모·행정병 |
| 에이전트 레지스트리 | `/react-agents` | 전체 |
| 에이전트 채팅 | `/react-agents/:id/chat` | 전체 |
| 실행 모니터링 | `/executions`, `/executions/:id` | 분석관·참모·행정병 메뉴에서 제공 |
| 일반 상황판 | `/situation` | 분석관·참모 메뉴에서 제공 |
| 센서 입력 | `/sensor` | 분석관 |
| 휴가 신청 접수 | `/leave-request` | 행정병 |
| 사용 매뉴얼 | `/manual` | 전체 |

지휘관이 `/situation`에 접근하면 `/dashboard`로 이동한다. 분석관이 아닌 사용자가 `/sensor`에, 행정병이 아닌 사용자가 `/leave-request`에 접근하면 `/dashboard`로 이동한다.

## 공통 화면 틀

로그인 후 56px 상단 헤더와 208px 좌측 메뉴를 사용한다.

상단 헤더에는 다음 정보를 표시한다.

- 제품명과 데모 표시
- 읽지 않은 알림 수
- 역할 선택
- 현재 역할과 지역
- 로그아웃 버튼

역할을 바꾸면 새 모의 세션을 받고 `/dashboard`로 이동한다. 현재 세션을 브라우저 저장소에 보존하지 않으므로 새로고침하면 로그인 화면으로 돌아간다.

좌측 메뉴는 역할별로 다르다.

- 분석관·참모: 대시보드, 두 빌더와 레지스트리, 실행 모니터링, 상황판, 사용 매뉴얼
- 행정병: 대시보드, 두 빌더와 레지스트리, 실행 모니터링, 사용 매뉴얼
- 지휘관: 상황판, 기본 에이전트, 사용 매뉴얼

## 역할 선택 로그인

네 역할 카드를 세로로 표시한다.

- 행정병
- 파주지역 분석관
- 정보·작전 참모
- 지휘관

선택한 역할의 업무 설명을 함께 보여준다. 비밀번호 입력은 없다. 로그인 버튼은 `/api/session`을 호출하고 성공하면 대시보드로 이동한다.

## 분석관·참모·행정병 대시보드

상단에는 역할과 지역, 입력 보조 버튼과 `에이전트 열기` 버튼을 표시한다.

- 분석관: `센서 입력`
- 행정병: `휴가 입력`
- 참모: 별도 입력 버튼 없음

대시보드 지표는 운영 워크플로우 수, 사용 가능 에이전트 수, 활성 실행 수와 승인 대기 수다. 그 아래에 `내 워크플로우`와 `내 에이전트` 패널을 같은 행에 배치한다. 각 카드는 상태, 설명, 버전 또는 연결 도구 수와 이동 버튼을 표시한다.

하단 `승인 및 알림`에는 최근 알림을 최대 다섯 건 표시한다. 알림을 누르면 읽음 처리 후 연결된 실행 상세로 이동한다. 승인 알림을 읽어도 승인 요청 자체는 처리될 때까지 대기 상태를 유지한다.

최근 실행 목록은 대시보드에 별도로 표시하지 않는다.

## 지휘관 상황판

지휘관은 대시보드 대신 상황판을 사용한다. 화면 순서는 다음과 같다.

1. 접경지역 COP 지도
2. 지휘관 기본 에이전트 채팅
3. 참모 종합 판단과 보고서 도착 알림

### COP 지도

OpenStreetMap을 사용하며 파주시, 연천군, 철원군을 선택한다. 우측 지역 목록에는 최신 지휘관 보고서가 참조한 지역 보고서의 제목과 위협 수준을 표시한다. 참조하지 않은 지역은 `최신 참모 보고에 포함되지 않음`으로 표시한다.

### 내장 지휘관 챗봇

지도 바로 아래에 지휘관 `GENERAL DEFAULT` 에이전트 채팅 전체를 넣는다. 별도 화면으로 이동하지 않고 다음 요소를 함께 사용한다.

- 왼쪽: 새 대화, 세션 시작일, 턴 수와 삭제
- 가운데: 저장된 대화, 추천 질문, 입력창과 스트리밍 답변
- 오른쪽: 공개 가능한 판단 및 도구 실행 과정

세션 이름은 최근 질문을 표시하지 않고 `2026.09.16 시작` 형식의 시작일만 표시한다. 기존 하단 카드형 지휘관 에이전트 레지스트리 영역은 제거한다.

### 종합 판단과 알림

최신 참모 종합 판단에는 제목, 위협 수준, 본문, 보고 시각, 참조 지역 수와 승인 참모를 표시한다. 카드를 누르면 전체 보고서 상세를 연다.

보고서 도착 알림은 실제 `COMMANDER` 보고서와 연결되는 항목만 표시한다. 클릭하면 읽음 시각을 저장한 뒤 보고서 상세를 연다. 원시 센서 이벤트와 승인 지역 보고서 카드 목록은 지휘관 화면에 표시하지 않는다.

## 워크플로우 레지스트리

레지스트리에는 현재 사용자 소유 워크플로우만 표시한다. 테이블 열은 다음과 같다.

- 워크플로우 이름과 지역
- 소유자와 역할
- 버전
- `DRAFT` 또는 `PUBLISHED` 상태
- 빌더 열기와 삭제 버튼

기본 제공 워크플로우에는 삭제 버튼이 없다. 현재 검색창과 필터 버튼은 시각 요소만 제공하며 실제 목록 필터링은 하지 않는다.

### 새 워크플로우

생성 창은 다음 항목을 받는다.

- 워크플로우 이름
- 설명
- 빈 캔버스 또는 현재 역할의 기본 템플릿

역할과 지역은 현재 세션 값으로 표시하며 사용자가 변경하지 않는다. 생성하면 `DRAFT` 상태로 저장하고 해당 빌더로 이동한다.

## 워크플로우 빌더

빌더는 전체 콘텐츠 영역을 사용한다.

```text
+--------------------------------------------------------------+
| 이름 · 상태 · 버전                   저장 / 검증 / 게시       |
+---------------+----------------------------+-----------------+
| 노드 팔레트   | React Flow 캔버스          | 노드 설정       |
| 역할별 노드   | 이동·연결·선택·삭제        | 연동·입출력·값  |
+---------------+----------------------------+-----------------+
| 시험 실행 · 예시 입력 · 실행 ID · 상태 · 실행 열기           |
+--------------------------------------------------------------+
| 시험 실행 후 노드별 trace 요약                               |
+--------------------------------------------------------------+
```

노드 팔레트는 역할별 여섯 개 노드를 그룹별로 보여준다. 노드 아래에는 연결 시스템 이름과 `MOCK` 상태를 표시한다. 노드를 누르면 새 노드를 캔버스에 추가한다.

캔버스는 노드 이동, 연결점 연결, 선택, 키보드 삭제, 확대·축소와 화면 맞춤을 지원한다. 위치는 화면 배치에만 사용하며 실행 순서는 연결로 결정한다.

설정 패널은 다음 내용을 제공한다.

- 연결 데이터 또는 외부 시스템
- 설계상 입력·출력 필드
- 노드 이름
- 필터 기준
- AI 모델과 시스템 프롬프트
- 작전 정보 조회 조건
- 노드 삭제

`저장`은 현재 정의를 `DRAFT`로 저장한다. `검증`은 현재 화면 정의를 서버 검증기에 보낸다. `게시`는 저장된 정의를 검증하고 새 버전을 만든다. `시험 실행`은 변경사항이 있으면 먼저 저장하고 역할별 고정 입력으로 실제 LangGraph 실행을 시작한다.

빌더는 시험 실행의 최신 상태를 약 1.5초 간격으로 조회한다. 승인 패널은 빌더 안에 표시하지 않으며 `실행 열기`로 실행 상세에 이동해 처리한다.

## 실행 모니터링

실행 목록은 실행 ID, 트리거 종류, 워크플로우와 버전, 시작 시각, 상태와 상세 링크를 표시한다. 검색창과 상태 필터 버튼은 현재 시각 요소이며 동작하지 않는다.

실행 상세는 왼쪽 읽기 전용 그래프와 오른쪽 시간순 trace로 구성한다. 각 trace는 노드 이름, 상태, 입력·출력 요약과 시각을 표시한다. 연결된 참모 실행이 있으면 헤더에서 이동할 수 있다.

승인 대기 실행은 전체 높이의 오른쪽 승인 패널을 자동으로 연다. 승인 패널에는 다음 내용을 표시한다.

- 승인 역할과 실행 ID
- 위협 수준 또는 휴가 처리 가능 여부
- AI 요약
- 근거 또는 관련 일정
- 승인용 초안
- 반려, 수정, 승인 버튼

`수정`은 편집창만 열며 실행을 재개하지 않는다. `수정 내용 승인`을 눌러야 `EDIT_APPROVE`로 재개한다. 현재 역할이 승인 담당자가 아니면 처리 버튼 대신 권한 안내를 표시한다.

## 에이전트 레지스트리

레지스트리 상단에는 목표 중심 ReAct 에이전트에 대한 짧은 설명을 보여준다. 목록에는 다음 정보를 표시한다.

- 이름, 설명과 기본 유형
- 역할과 소유자
- 연결 도구 수
- 최대 반복 횟수
- 생명주기와 버전
- 빌더 또는 채팅 실행 버튼

범용형과 임무 특화형 시스템 기본 에이전트를 각각 `GENERAL DEFAULT`, `MISSION DEFAULT`로 표시한다. 기본 에이전트는 삭제할 수 없고 빌더에서 연동을 읽기 전용으로 확인한다. 지휘관에게는 새 에이전트와 빌더 버튼을 표시하지 않는다.

분석관·참모·행정병은 이름을 입력해 커스텀 에이전트를 만든다. 설명은 현재 고정 기본 문구로 생성하고, 이후 빌더에서 수정한다.

## 에이전트 빌더

```text
+--------------------+------------------------+------------------+
| 연동 카탈로그      | 사용자 목표와 ReAct    | 에이전트 설정    |
| 전체/데이터/시스템 | 런타임·리소스 그래프   | 이름·모델·프롬프트|
+--------------------+------------------------+------------------+
```

연동 카탈로그는 역할에 허용된 항목만 표시한다. 각 카드에는 이름, 설명, `MOCK`, `DATA` 또는 `SYSTEM`, capability의 접근 유형과 승인·워크플로우 전용 여부를 표시한다.

커스텀 에이전트는 카드를 눌러 연결을 추가·해제한다. 중앙 그래프는 선택한 연동을 `사용자 목표 → ReAct 런타임 ↔ 연결 리소스` 형태로 보여준다. 우측에서는 이름, 설명, 모델, 최대 반복 횟수와 시스템 프롬프트를 편집한다.

시스템 기본 에이전트의 카탈로그와 설정은 읽기 전용이다. 커스텀 에이전트는 연결을 하나 이상 선택해야 저장할 수 있고, 게시 후에만 채팅을 실행한다.

## 독립 에이전트 채팅

독립 채팅 화면과 지휘관 내장 채팅은 같은 컴포넌트와 API를 사용한다. 구성은 세 열이다.

- 세션: 새 대화, 시작일, 턴 수, 삭제
- 대화: 컨텍스트 정보, 추천 질문, 기록, 입력창
- 실행 과정: 판단 요약과 도구 관찰

추천 질문을 누르면 입력창에만 채우고 자동 실행하지 않는다. 실행 버튼 또는 `Enter`로 제출한 뒤 사용자 메시지를 대화에 표시한다. `Shift+Enter`는 줄바꿈이다.

실행 중에는 입력, 새 대화, 세션 전환과 삭제를 비활성화한다. 완료된 요청은 중앙 대화와 DB에 저장한다. 과거 세션을 선택하면 사용자 요청과 최종 답변은 복원하지만 오른쪽의 과거 실행 타임라인은 복원하지 않는다.

## 센서 입력

센서 ID와 지역은 `파주-감시센서-03`, `경기도 파주시`로 고정한다. 사용자는 다음 값을 조절한다.

- 이벤트 종류: 이동체 감지, 열원 감지, 경계선 접근
- 탐지 개체 수: 1~12개
- 신뢰도: 50~99%

우측에는 전송 JSON과 분석 기준 안내를 보여준다. 전송이 성공하면 실행 ID와 상태, 실행 상세 이동 버튼을 표시한다.

## 휴가 신청 접수

군번, 성명, 소속, 휴가 종류, 시작일, 종료일과 신청 일수를 입력한다. 휴가 종류는 정기·포상·청원 휴가를 지원하고 신청 일수는 1~15일이다.

우측에는 워크플로우 입력 JSON과 자동 조회 항목을 표시한다. 접수 후 신청 ID, 잔여 휴가 12일, 실행 상태와 검토 화면 이동 버튼을 보여준다.

## 일반 상황판과 보고서 상세

분석관은 파주시만, 참모는 파주·연천·철원을 선택할 수 있다. 지도 아래에는 현재 역할이 볼 수 있는 승인 보고서 카드를 표시한다. 카드를 누르면 종류, 제목, 승인 내용, 지역, 위협 수준, 승인자·시각과 원본 실행을 읽기 전용 모달로 연다.

고급 군사 GIS 레이어는 제공하지 않는다.

## 오류와 접근성

- API 오류는 관련 화면 안에 한국어 메시지로 표시한다.
- 실행 실패를 성공 애니메이션으로 대체하지 않는다.
- 버튼과 입력 요소는 키보드로 접근할 수 있어야 한다.
- 상태는 색상과 텍스트를 함께 사용한다.
- 비공개 사고 과정이라는 표현을 사용하지 않고 공개 가능한 판단 요약으로 설명한다.
